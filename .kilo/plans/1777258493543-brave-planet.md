# NEXUS OS Project Upgrades Plan

## Project Overview
**NEXUS OS** (also referenced as Atheletia/Gemini Cortex) is an AI-powered personal desktop application built with Tauri v2 (Rust) + React/TypeScript. It features activity tracking, AI chat, notes (Brain), schedule management, music player, LeetCode tracker, and more.

---

## Current State Assessment

### Strengths
- Well-architected with clear separation between frontend (React/Zustand) and backend (Tauri/Rust)
- Comprehensive feature set covering productivity, AI chat, activity tracking, and personal knowledge management
- Hybrid RAG system partially implemented with embedding pipeline, query router, and evidence pack builder
- Good documentation in README.md

### Critical Issues Found

| Issue | Severity | Details |
|-------|----------|---------|
| **File Size Violations** | High | `retrieval.rs` (2158 lines, cap: 2000), `query_engine.rs` (1738 lines, target: 1300) |
| **Inconsistent Naming** | Medium | Project called "NEXUS OS", "Atheletia", and "Gemini Cortex" in different files |
| **Incomplete Hybrid RAG** | Medium | Steps 2-7 of RAG implementation pending (ingestion hooks, privacy controls, etc.) |
| **Missing AGENTS.md** | Low | No agent instruction file at project root |

## Proposed Upgrades

### Phase 1: Code Quality & Refactoring (Priority: P0)

#### 1.1 Split Oversized Rust Modules
**Rationale**: Files exceeding line limits reduce maintainability and violate project standards.

| File | Action | Target Structure |
|------|--------|----------------|
| `src-tauri/src/intent/retrieval.rs` (2158 lines) | Split into 6 modules | `retrieval/mod.rs`, `chunking.rs`, `embedding.rs`, `search.rs`, `vault.rs`, `summaries.rs`, `privacy.rs` |
| `src-tauri/src/services/query_engine.rs` (1738 lines) | Split into 4 modules | `query_engine/mod.rs`, `tools.rs`, `scope.rs`, `streaming.rs` |

**Tasks:**
- [ ] Create module directories
- [ ] Move types to `mod.rs`
- [ ] Extract embedding logic to `embedding.rs`
- [ ] Extract search logic to `search.rs`
- [ ] Extract vault logic to `vault.rs` (merge with `retrieval_vault_index_helpers.incl.rs`)
- [ ] Extract summary rollup to `summaries.rs`
- [ ] Create `privacy.rs` stub for redaction/retention
- [ ] Update all call sites in `lib.rs`, `chat.rs`, `diary.rs`, etc.

#### 1.2 Standardize Project Naming
**Current State:**
- `package.json`: "name": "atheletia"
- `tauri.conf.json`: "productName": "Atheletia"
- `metadata.json`: "name": "Gemini Cortex"
- README.md: "NEXUS OS"

**Recommendation:** Choose one name (suggest **"NEXUS OS"** as it's most descriptive) and standardize across:
- [ ] Update `package.json`
- [ ] Update `tauri.conf.json`
- [ ] Update `metadata.json`
- [ ] Update `Cargo.toml`
- [ ] Update window titles in `src-tauri/src/lib.rs`

### Phase 2: Complete Hybrid RAG Implementation (Priority: P0-P1)

Based on `plans/hybrid-rag-architecture.md` and `docs/hybrid-rag-todo.md`.

#### 2.1 Complete Ingestion Hooks (Step 2)
**Status:** ~60% complete

- [ ] Auto-chunk chat messages on send (`chat.rs` → `chunking::ingest_chat_message`)
- [ ] Auto-chunk diary entries on save (`diary.rs` → `chunking::ingest_diary_entry`)
- [ ] Auto-chunk file changes on detection (`file_monitor.rs` → `chunking::ingest_file_change`)
- [ ] Add invalidation/dedupe rules for entity updates

#### 2.2 Embedding Pipeline Polish (Step 3)
**Status:** ~80% complete

- [ ] Add model dimension detection (store actual dimensions instead of hardcoding 768)
- [ ] Add failed-job retry backoff with exponential delay

#### 2.3 Query Router Polish (Step 4)
**Status:** ~85% complete

- [ ] Add structured route SQL-only fast path (skip FTS/vector for structured queries)
- [ ] Add mixed route SQL filter pushdown to all candidate sources

#### 2.4 Evidence Pack Builder Polish (Step 5)
**Status:** ~80% complete

- [ ] Add adjacent chunk merging for consecutive chunks from same entity

#### 2.5 Long-History Mode (Step 6)
**Status:** ~30% complete

- [ ] Wire summaries into retrieval (`fetch_summary_candidates`)

#### 2.6 Privacy Controls (Step 7)
**Status:** ~10% complete
